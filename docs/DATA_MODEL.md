# Data model

All files in `web/public/data/` are generated by the pipeline. The web app never edits them. TypeScript types for each live in `web/lib/types.ts` and must match exactly.

## `species.json` — the catalogue

Array of objects, sorted by catalogue number.

```ts
type IucnCode = "CR" | "EN" | "VU" | "NT" | "LC" | "DD" | "NE";
type Harvest = "safe" | "careful" | "do-not-harvest" | "unknown";
type EmaStatus = "well-established" | "traditional" | "none" | "unknown";
type RiskLevel = "low" | "moderate" | "high" | "critical";
type DataQualityFlag = "gbif_synonym_match" | "gbif_shared_key" | "gbif_no_match";   // automatic, see pipeline/chloris/flags.py
type ReviewFlag = "name_only_match" | "native_status_check";                         // for the science lead

interface Species {
  slug: string;              // "origanum-dictamnus"
  cat: string;               // "CHL-0412" catalogue number
  name: string;              // accepted scientific name, no authors
  authors: string;
  family: string;
  nameEl: string | null;
  nameEn: string | null;
  powoId: string | null;     // for POWO link and Pl@ntNet matching
  gbifKey: number | null;
  endemic: boolean;          // endemic to Greece (GRC/KRI/EAI)
  iucn: IucnCode;            // "NE" = not assessed; "DD" = data deficient. Neither is a low-risk category.
  iucnLabel: { en: string; el: string };   // NE → "Not assessed" / "Δεν έχει αξιολογηθεί". Always show this, never the bare code.
  dataQuality: DataQualityFlag[];   // [] when clean; the app shows a small "data note" and /about explains each flag
  review: ReviewFlag[];             // [] when nothing to review
  reviewNote: string | null;        // reason text from config/review_overrides.csv
  medicinalSource: "wcups" | "curated";
  risk: {
    score: number;           // 0–100 integer
    level: RiskLevel;
    atRisk: boolean;
    parts: {                 // points contributed; null = not enough data
      iucn: number; endemic: number; rarity: number;
      decline: number | null; unprotected: number; fire: number | null;
    };
  };
  stats: {
    records: number; cells: number;
    recordsOld: number; recordsNew: number;
    declineRatio: number | null;
    protectedShare: number | null;  // 0–1; null = Natura 2000 join not available
    fireShare: number | null;
    firstYear: number | null; lastYear: number | null;
  };
  featured: boolean;
  curated?: {                // only when featured
    usesEn: string; usesEl: string;
    prepEn: string; prepEl: string;   // traditional preparations (science lead); "" = not reviewed yet
    ema: EmaStatus; emaUrl: string | null;
    harvest: Harvest;
    substitutes: string[];   // slugs
    reviewedBy: string | null;
  };
  photo?: { url: string; credit: string; licence: string; source: string };
}
```

## `names.json` — lookup for search and scan matching

```ts
{
  byName: Record<string, string>;   // normalised name (accepted + synonyms, lowercase, no authors) → slug
  byPowo: Record<string, string>;   // POWO id → slug
  byGbif: Record<string, string>;   // GBIF key → slug
}
```

## `cells.json` — hotspots

```ts
{
  size: number;                      // 0.1
  cells: Array<{
    id: string;                      // "382_237" → lat 38.2–38.3, lon 23.7–23.8
    s: number[];                     // indexes into species.json
    nAtRisk: number; nEndemic: number;
    protected: number | null;        // 0–1 fraction of cell in Natura 2000; null = not available
    hotspot: boolean | null;         // has ≥1 at-risk species AND protected < 0.5; null if protected is null
  }>;
}
```

## `occ/<slug>.json` — one species' cells, loaded on demand

```ts
Array<{ c: string; n: number; f: number | null; l: number | null; o: number; w: number }>
// c = cell id, n = records, f/l = first/last year, o = records in old period, w = records in new period
```

## `evidence/<slug>.json` — evidence cards, featured species only

Lazy-loaded per species (not part of `species.json`). Built from `pipeline/config/evidence.csv` (edited by the science lead; version label in `evidence_meta.yaml`). `meta.json` lists which species have a file (`evidenceSlugs`), the collection `evidenceVersion`, and `evidenceCounts` (cards and distinct safety notes per file, used to size the skeleton).

```ts
type EvidenceKind = "traditional_use" | "human_research" | "animal_or_lab" | "review" | "regulatory_monograph";
type EvidenceSourceType = "pubmed" | "doi" | "ema_monograph" | "other";

interface EvidenceFile { version: string; slug: string; entries: EvidenceEntry[] }  // 1 to 2 entries

interface EvidenceEntry {
  kind: EvidenceKind;
  title: string;
  finding: string;          // neutral, own words, at most 2 sentences, includes mixed or negative results
  limitations: string;      // at most 2 sentences
  plantPart: string;        // "unknown" when the source does not state it
  preparation: string;      // "unknown" when not stated
  design: string;           // "unknown" when not stated
  sourceType: EvidenceSourceType;
  sourceId: string;         // PMID, DOI or monograph reference
  sourceUrl: string;
  verifiedAt: string;       // YYYY-MM-DD, or "unknown" when unverified
  verification: "checked against linked source" | "unverified";
  specialistReview: string; // "pending" until the science lead changes it
  safetyNote: string | null;
}
```

Rules enforced by the pipeline and by `npm run validate-data`:
- only featured species; at most 2 entries each; no empty field (write `unknown`); `safety_note` may be empty;
- `verification` is `"checked against linked source"` only with a real `source_url` and a `verified_at` date, and may be set only after the source page was actually fetched and read;
- no dosing anywhere (quantities with units, "daily dose", "times daily", "posology" are rejected).
- Entry text stays in English; the UI labels it "Source text in English" in Greek.

## `natura.geojson`, `fires.geojson`

Simplified polygons. Properties: Natura `{ code, name, type }`; fires `{ year }`.

## `meta.json`

```ts
{
  generatedAt: string;
  sources: Array<{ name: string; version: string; url: string; licence: string; doi?: string }>;
  counts: { greekNatives: number; medicinal: number; featured: number; records: number; cells: number; atRisk: number };
  scoring: object;                  // copy of scoring.yaml
  verdicts: { version: string; min_records: number; protect_iucn: IucnCode[]; protect_levels: RiskLevel[]; care_levels: RiskLevel[]; care_if_endemic: boolean };  // copy of verdicts.yaml
  notes: string[];                  // e.g. "Fire layer skipped: no data"
  flagLegend: Record<string, string>;  // text for every DataQualityFlag / ReviewFlag
  iucnLabels: Record<IucnCode, { en: string; el: string }>;
}
```

## Firestore: `sightings` collection

```ts
interface Sighting {
  slug: string | null;              // null if not in Chloris
  scientificName: string | null;    // from Pl@ntNet or user
  confidence: number | null;        // 0–1
  note: string | null;              // max 280 chars
  lat: number; lng: number;         // any Firestore write must be rounded to 0.1°
  generalised: boolean;            // true for every Firestore write
  uid: string;                      // anonymous auth uid
  createdAt: Timestamp;             // serverTimestamp()
  capturedAt: string;               // ISO, device time (may differ when synced later)
  verified: boolean;                // always false on create
}
```

**Security rules (must be deployed):**
- read: authenticated owner only (`resource.data.uid == request.auth.uid`).
- create: signed-in (anonymous) users only, `uid == request.auth.uid`, `verified == false`, lat within 34.5–42.0 and lng within 19.0–30.0, both coordinates on the 0.1° grid, `generalised == true`, `note` ≤ 280 chars, only the fields above. Client-side `atRisk` is not trusted by Firestore. Device-only sightings may retain 0.001° positions for non-risk species; any future sync must first reduce them to 0.1°.
- update, delete: nobody (verification is done by hand in the console for the hackathon).

## Device storage (offline)

- **Firestore persistent local cache** queues sighting writes.
- **IndexedDB** (`idb-keyval`) queue `pendingScans`: `{ id, photoBlob, lat, lng, capturedAt }`. Processed by `/api/identify` when online, then removed. Photos never leave the device except to Pl@ntNet.
